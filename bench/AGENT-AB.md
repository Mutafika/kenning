# Real-agent A/B — the same tasks, with and without kenning

Generated by `./bench/agent-ab.sh` (headless `claude -p`, Claude Opus 5.5, 2026-09-28). Scored by `bench/agent-ab-score.py`.

The agent / beyond suites in `bench/RESULTS.md` are **byte ratios** against a lower-bound model of the grep path; they
don't measure what a real agent actually gains. This one has a real agent solve the same tasks and compares
**cost, turns, wall time and correctness**.

## Conditions

| Condition | Tools | Guidance (appended to the system prompt) |
|---|---|---|
| **A** | Read / Grep / Glob / read-only Bash (rg grep sed cat head tail find ls wc awk) + **kenning** | Full guide (~15KB; the CLAUDE.md of the time, now `docs/GUIDE.md`) |
| **B** | Read / Grep / Glob / read-only Bash | none |
| **C** | same as A | Short guide `agent-ab/guide-slim.md` (~1.5KB) |

A / B / C for the same task run concurrently (same load and prompt-cache conditions). 3 runs each, median.
Calls outside the allowlist (compound commands such as `for` loops) were denied a few times in every condition
(A 2 / B 4 / C 4, across all runs).

## Tasks and ground truth (built independently of kenning)

| Task | Question | How the ground truth was built |
|---|---|---|
| tokio-add-permits | Every call site of `sync::Semaphore::add_permits` (12) | rename → error locations of `cargo check --all-targets` |
| tokio-joinset-spawn | Sites to fix when adding an argument to `JoinSet::spawn` (25, buried among 1,140 same-named `spawn`) | same + 5 under cfg(loom) |
| enchudb-oplog-open | Sites to fix when changing `OpLog::open` (24; 12 types have an `open`, 209 calls) | same (`truth-rename.sh`) |
| enchudb-leafstore-insert | Sites to fix when changing `LeafStore::insert` (44; 562 `insert` calls) | same |
| tokio-sleep-reset-tests | Tests to run after changing `Sleep::reset` (35) | put a marker in the body and run every test one by one = the tests that actually reach it |
| tokio-block-on-park | The call chain from `block_on` to the thread parking | 8 hops traced by hand (every run reached all 8) |

### Round 5 — after removing the reasons agents fell back to grep (D, Haiku / Opus, commit 8441d22 + conditional-definition fix)

We classified the ~310 times an agent fell back to grep in the kenning runs. Most common first: (1) re-counting misses
with grep after `callers` (it didn't show where the calls resolved to another same-named definition went), (2)
checking aliases (`use X as Y`), (3) reading same-named definitions with `grep -n "fn X" -A5`, (4) filling real kenning
gaps (misses in `tests`). For (1) we now list the destination per definition, for (3) the guide gained
`read <name> path:`, and part of (4) was fixed (definitions inside `cfg_rt!` were not confirmed from outside).

| Task | Haiku D (before → after) | Correctness (before → after) |
|---|---|---|
| tokio-joinset-spawn | $0.09 / 12 turns → **$0.03 / 2 turns** (one kenning call) | recall 100% → 100% (76% on an intermediate build) |
| tokio-add-permits | $0.05 / 5 → $0.01 / 2 | 100% → 100% |

### Round 6 — a candidate layer in `tests` / `impact`, and `use .. as` aliases (D, Haiku / Opus, INDEX_VER 28)

We closed the two remaining gaps from round 5. (a) `tests` / `impact` followed only confirmed edges — now whatever is
reachable through at most one call that `callers` lists under ⚠ unresolved candidates (unknown receiver type / via a
trait) is listed in the same output as `[c1]` (names with so many same-named definitions that they exceed 64
candidates are not followed and are named on a `#` line; `Drop::drop` is excluded since it can't be called by name).
(b) `g()` after `use a::f as g` was missing entirely from the name match of `callers f` (aliased fns /
`{self as aa}` / associated functions of an aliased type) — it is now stored under the original name. Cross-checks
against rust-analyzer stay at 0 wrong confirmations on all 4 repos. The baseline is round 5 (same tasks, same 3 runs,
the day before).

| tokio-add-permits | $0.01 / 2 / 100% → same | $0.04 / 4 / 1.7 → $0.05 / 4 / 2.0 |

- **Haiku's test selection went from 74% to 100%.** It gets there by answering with a single kenning output ([d] 45 +
  [c1] 39) as is. Precision drops by however much of the statically reachable superset it lists (the safe side for
  tests to run). Haiku made 0 grep calls outside block-on-park.
- **Opus's grep-like calls did not go down** (14.7 → 16.3 per task set, within the noise of 3 runs). Reading them,
  they are habits rather than kenning gaps: slicing lines with `sed -n A,Bp` (most of block-on-park; `read <path>:A-B`
  exists), searching terms that include `.md` files (`text` exists), and re-counting the `callers` answer with
  `grep add_permits(`. Adding features won't bring this kind to 0.
- **block-on-park is a different gap.** `path Runtime::block_on park` stops at the first `park` (`Context::park`, 4

### Round 7 — pattern-binding types / same-name delegation in `path` / guidance for cut lists (D, Haiku / Opus, INDEX_VER 29)

What round 6 called "outside the static call graph" for block-on-park was wrong — in `match self { E::V(x) => x.park() }`
the type of x is written in the variant definition. (a) Field types of enum variants / tuple structs now go into the
field table, and receivers in the patterns `E::V(x)` / `E::V { f }` / `Self::V(x)` / `T(x)` and `self.0` are followed
(`V(x)` after `use E::*` can be confused with a same-named tuple struct, so it is not confirmed). Typed confirmations
in the syn layer: tokio +39 / ripgrep +32 / enchudb +116; cross-checks against RA stay at 0 wrong confirmations on all
4 repos. (b) When `path X park` stops at the first `park`, the delegations from the end to same-named definitions
(including enum dispatch targets) are printed as a tree. (c) A list cut by `--limit` now says how to get all of it in
a form you can type (today: "`--limit N` or `--limit 0`"), and `--limit 0` = no limit.

| Task | Haiku round 6 → round 7 | Opus round 6 → round 7 |
|---|---|---|
| tokio-block-on-park | $0.32 / 51 turns → $0.30 / 46 turns. All 3 runs answer down to the io driver's `turn` | $0.17 / 7 → $0.15 / 5. All 3 runs down to `io::Driver::turn` |
| tokio-sleep-reset-tests | $0.05 / 4 / 100% → (before c) 74% → (after c) **$0.05 / 3 / 100%** | $0.22 / 8 / 100% → $0.26 / 8 / 100% |
| The other 4 tasks | same ($0.01–0.03 / 2 turns / 0 grep) | same (100% correct) |

- **The fall back to 74% on test selection was caused by how kenning's output was cut.** With the default
  `--limit 50`, 50 of 84 results were shown and Haiku answered with exactly those (a hint that just said "use --limit
  for everything" didn't tell it how many there were). After (c), all 3 runs are 100%.
- **Haiku still does 20 Reads on block-on-park because the question asks about a runtime branch.** `path
  Runtime::block_on Driver::turn` prints all 11 hops at once, but the shortest route goes through `park_yield` —
  whether it is the `park` branch taken "when the future isn't ready" can only be decided by reading the body. Not a
  kenning gap.
- Opus's grep-like calls are the same as round 6 (16–17, habit).

## How to read this (honestly)

- **Correctness doesn't differ.** Opus with grep alone also finds all 25 sites among 1,140 same-named `spawn`. kenning's
  value isn't "grep gets it wrong" — it's **reaching the same answer in half the turns at ~60% of the cost**.
- **The gap is widest for test selection** (B $0.56–0.65 and 93–122 sec, A / C $0.19–0.27 and 47–51 sec). The more a
  question follows transitive calls, the more grep round trips it takes — the same direction as "the deeper the
  question, the wider the gap" in `RESULTS.md`.
- A / C show 65% precision on test selection because they also list tests that **are reachable statically** but were
  not hit at runtime (54 for 35). That's the safe side for tests to run after a change. B hit exactly 35 but at 2.4x
  the cost.
- **Shorter guidance pays.** The full CLAUDE.md (A) makes the agent read ~15KB every turn, so on easy tasks it loses to
  B on input tokens. The ~1.5KB guide (C) uses 1.2–1.7x fewer input tokens than B too.
- B's cost (no kenning) itself moved between rounds 1 and 2, $1.49 → $1.60. Compare ratios within the same round. With
  3 runs per condition, one model and prompt-cache effects, cost moves by about ±30% (a single run of the same task
  ranged $0.04–0.13).

## kenning gaps found and fixed in this experiment

Found by comparing round-1 answers with the ground truth. `kenning tests Sleep::reset` listed only 24 of the 35
tests that actually reach it at runtime (the agents got to 100% by filling in with grep).

- `callers Type::name` (a qualified name) looked up the name match with the qualified name as is, silently reducing
  candidates to 0.
- When a same-named free function existed in another file, even calls to a helper in the same file (`tmp_dir()` /
  `walk()`) were left unconfirmed as "multiple same-named" — fixed to follow Rust's rule that items in your own module
  take precedence. enchudb's baked confirmed rate went 80.5% → 89.5% (multiple same-named 2,572 → 25).
- The module of `time::sleep` was not derived from the file location (`src/time/sleep.rs`).
- Receivers through free-function return values and `Box::pin(x)` / `.as_mut()` were not inferred.
- `callers` had no `path:` / `crate:` filter, so there was no way to narrow same-named free functions.

Every fix went in while keeping 0 wrong confirmations against rust-analyzer (`kenning bench infer`) on 4 repos. The
remaining 11 are receivers behind the generic `tokio_test::task::spawn(..).into_inner()` / `tokio::pin!`, and calls
through a trait (`Stream::poll_next`) — outside the static call graph.
